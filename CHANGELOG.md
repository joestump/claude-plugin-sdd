## [5.4.0] — 2026-09-20

PRDs become a fourth authored artifact type — optional, client-facing-only, and enforced rather than asserted — plus the traversal-direction fix that adding them exposed, and a docs-site page that had never been published.

### Added

- **`/sdd:prd` — Product Requirements Documents as an optional pre-ADR artifact** ([ADR-0036](docs/adrs/ADR-0036-prd-as-optional-pre-adr-product-intent.md), SPEC-0037, [#244](https://github.com/joestump/claude-plugin-sdd/pull/244), [#245](https://github.com/joestump/claude-plugin-sdd/pull/245)): client-facing requests arrive vague — "add a dashboard", "support SSO" — and the gap between that ask and a rigorous spec is the interrogation that precedes it. A PRD captures product intent in the client's language and carries a sign-off boundary that `spec.md` genuinely cannot: the spec pair is an engineering contract, the PRD is the commercial one. PRDs live in `docs/prds/` with sequential `PRD-XXXX` IDs, are produced grill-first, carry EARS-shaped success criteria and a blast-radius collision check confirmed against the codebase, and declare `governs:` edges into the ADRs and specs they produce. **They are optional and client-facing-only** — most ADRs are pure engineering decisions with no product intent upstream, so the absence of a PRD is never reported as a finding, in any skill. Template content contributed by @surveygate.
- **PRD enforcement across the toolchain** ([#249](https://github.com/joestump/claude-plugin-sdd/pull/249)): SPEC-0037 specified status gates, EARS validation, graph visibility and qmd isolation, and `/sdd:prd` documented all of it as live — but none of it existed, so a PRD authored against 5.3.0 got no gate checking, was invisible to the graph, and landed in no collection, silently. `/sdd:graph` now scans PRDs as their own node type (`governs:` / `related:` only, with `orphans` reporting a PRD only once it reaches `approved` or `shipped`); `/sdd:check` and `/sdd:audit` validate the gates, the EARS shape, and that a committed PRD governs something real; `/sdd:index` gives PRDs the `{repo}-prds` collection rather than letting the specs mask (`**/*.md`) swallow them; and `list`, `status`, `prime`, `docs` and `init` gain PRD awareness. `shared-patterns.md § "Artifact Path Resolution"` resolves `{prd-dir}` from `- Product Requirements Documents are in {path}`, defaulting to `docs/prds/`.
- **Grill-first gains a round format and a named anti-pattern** ([#247](https://github.com/joestump/claude-plugin-sdd/pull/247)): the pattern told skills to number each question with a recommended answer and never showed one, so every caller invented a layout. It now carries the concrete `❓ Q1` / `➡️ recommendation` shape, an explicit "asking the user for facts" anti-pattern with examples, and the clarification that a running exploration blocks only the questions downstream of it. Contributed by @elirubel.

### Fixed

- **`/sdd:graph impact` and `ancestors` walked the wrong way through `governs:` and `enables:`** ([#249](https://github.com/joestump/claude-plugin-sdd/pull/249)): both verbs partitioned edges by the `derived` flag, treating "authored" as a synonym for "upstream". It is not — `governs` and `enables` point downstream — so `impact` climbed *upstream* through `governed-by` and `ancestors` descended *downstream* through `governs`. [#237](https://github.com/joestump/claude-plugin-sdd/pull/237) normalized exactly this for cycle detection and the fix was never applied to traversal. The error hid wherever a relationship is authored from both ends, and was already live for the 14 ADRs in this repo authoring `governs:`: `impact SPEC-0007` climbed to its governing ADR and then sprawled through that ADR's whole subtree — 34 lines of output for a spec with one real dependent — while `ancestors ADR-0014` reported the specs it *governs* as its ancestors, and `ancestors ADR-0009` reported none at all despite authoring `extends:`. Traversal now splits on direction, and parallel same-direction edges (the legal dual `governs:`/`implements:` authoring) collapse to one row instead of printing the target twice. SPEC-0018 is amended to define the split. This changes output for 114 of 185 artifact/verb combinations.
- **The `/sdd:index` documentation page had never been published** ([#250](https://github.com/joestump/claude-plugin-sdd/pull/250)): `transform-skills.js` writes one page per skill to `docs-generated/skills/{name}.mdx` and then writes the hero-tile overview to `docs-generated/skills/index.mdx` — after the loop. The plugin ships a skill named `index`, so its page was generated and then silently overwritten on every build. Nothing failed: Docusaurus reports broken links as warnings, and the two it emitted (the sidebar entry and the hero tile, both pointing at `/skills/index`) read as a routing quirk rather than a missing page. The skill's page now renders at `index-skill.mdx` while keeping its `/skills/index` slug, so the sidebar entry, the hero tile, and the quick-reference guide all resolve. The docs site builds with zero broken links.

## [5.3.0] — 2026-09-16

Authoring-skill hardening traced from a downstream audit of a plugin-generated project, docs-site cross-reference fixes, two critical dependency bumps, a lightweight ADR tier, and a false-cycle fix in `/sdd:graph` — on top of CI secret scanning and cross-harness portability.

### Added

- **Secret scanning in CI** ([#208](https://github.com/joestump/claude-plugin-sdd/issues/208)): `ci.yml` had jobs for lint and test but nothing stopping a credential from landing. A new separately-named `gitleaks` job runs `make scan` (`scripts/gitleaks-scan.sh`), which scans git history and the working tree and always redacts findings so no secret value reaches a CI log. The job clones with `fetch-depth: 0` — the default shallow clone has no history to scan — and installs a version-pinned, sha256-verified gitleaks binary. `make check` now runs `test`, `lint`, and `scan`, so CI and local runs stay the same checks.
- **Harness portability across Codex CLI, OpenCode, and Crush**: new `references/harness-compat.md` maps every Claude Code-specific tool surface the skills name (`AskUserQuestion`, `Task`, `TeamCreate`/`SendMessage`, `Task*`, `ToolSearch`, `mcp__*`, `${CLAUDE_PLUGIN_ROOT}`) to per-harness equivalents and documented fallbacks, defines the project memory file resolution (`CLAUDE.md` / `AGENTS.md` / `CRUSH.md`), plugin-root resolution, permissions equivalents, and worktree placement rules. All 20 skills carry a standard portability note, `shared-patterns.md` generalizes Config Resolution to the memory file, `/sdd:init` selects the harness-native memory file and gates the `.claude/settings.local.json` permissions step to Claude Code, and `/sdd:work`'s `/autofix-pr` stage skips cleanly (without filing version issues) on harnesses that can never ship the built-in.

- **`/sdd:spec` validates artifacts before writing** ([#217](https://github.com/joestump/claude-plugin-sdd/pull/217)): new Step 4c runs consistency validation — numbering, edges, and links — after drafting and before anything is written to disk. First of five hardening PRs traced from a downstream audit that reviewed every ADR and OpenSpec in a plugin-generated project to find which defects came from the skills rather than the project.
- **Spec frontmatter edges render in the body** ([#219](https://github.com/joestump/claude-plugin-sdd/pull/219)): frontmatter edges were machine-readable only — a human reading the raw markdown or the rendered docs page never saw the graph, so downstream projects hand-wrote their own "Related ADRs" headers. Specs now carry a generated Related Artifacts section.
- **`/sdd:status --backfill`** ([#221](https://github.com/joestump/claude-plugin-sdd/pull/221)): artifacts predating the YAML-frontmatter template had no supported path to the canonical format, since `/sdd:status` deliberately preserves legacy inline-bullet status lines. Backfill migrates them.
- **`/sdd:adr --quick`** ([#232](https://github.com/joestump/claude-plugin-sdd/pull/232)): a lightweight tier for single-option decisions. Amends SPEC-0003 and ADR-0003 so the two-substantively-argued-options + Mermaid-diagram rule applies to full-tier ADRs, and a single-option decision gets a compact record instead of a forced sham comparison.

### Fixed

- **Tier 1 mutation updates now check the qmd collection's context for drift** ([#211](https://github.com/joestump/claude-plugin-sdd/issues/211)): a collection has two surfaces — the index and the human-written context blurb — and `qmd update` refreshes only the first. Since `/sdd:index` requires a blurb on every collection and those blurbs enumerate the corpus ("ADR-0001 through ADR-0012", accepted-vs-proposed groupings), the context silently went stale while retrieval kept working perfectly, and qmd prepended the wrong text to every retrieved chunk. Sharpest case: after a `proposed` → `accepted` transition the context contradicted the artifact's own frontmatter, with both returned in the same result. `qmd-helpers.md` § "Update Patterns" now documents the two-surface split and a drift check (`qmd context list -c {collection}`), and `/sdd:adr`, `/sdd:spec`, and `/sdd:status` run it after their Tier 1 update — best-effort, silent when the context still holds, one line when it does not, and never rewriting the blurb unprompted.
- **`/sdd:report-friction` no longer loses the entire report when a label is missing** ([#211](https://github.com/joestump/claude-plugin-sdd/issues/211)): Step 4 mandated the `skill-friction` label, which did not exist in this repository, and `usability` did not either. `gh issue create --label` is atomic, so a missing label meant **no issue was created at all** — and creating one needs write access the reporter does not have, since the whole point is filing from someone else's project. Both labels now exist, and labelling is documented as try-then-omit: on a label error, retry once unlabelled and tell the user which labels were dropped. An unlabelled issue carrying the full report beats a missing one.
- **`/sdd:work` and `/sdd:review` worktree cleanup now deletes the local branch, not just the worktree** ([#209](https://github.com/joestump/claude-plugin-sdd/issues/209)): both skills' cleanup step ran `git worktree remove` and stopped there — the branch ref created by `git worktree add -b` was never deleted, so every completed issue or PR left a permanent stale local branch behind. Left unchecked across a project's lifetime this accumulates without bound (one real project reported ~140 leftover branches). Both skills now follow a new **Worktree Cleanup** pattern in `shared-patterns.md`: remove the worktree, then delete the branch ref. The delete decision comes from the tracker's merge state, not from `git branch -d`'s exit code — `-d` checks "merged into its upstream, or into HEAD if no upstream", which is not a merged-into-`main` check, so on the default squash merge strategy it refuses precisely the merged branches that were piling up (the `[origin/…: gone]` ones). The pattern therefore tries `-d` first, and on refusal asks the tracker: confirmed-merged branches get `-D`, everything else is kept with a one-line note. A worktree with uncommitted changes is kept along with its branch rather than force-removed.
- **Scaffolded docs sites now typecheck**: the five badge components shipped in `templates/docusaurus/src/components/` (`DateBadge`, `DomainBadge`, `PriorityBadge`, `SeverityBadge`, `StatusBadge`) annotated their return type as `JSX.Element`. `package.json` declares React 18, but the `@types/react` hoisted in from Docusaurus is v19, which removed the global `JSX` namespace, so `tsc` failed with `TS2503: Cannot find namespace 'JSX'` in every site `/sdd:docs` scaffolds. All five now use `React.JSX.Element`, which resolves under both type versions.
- **`/sdd:prime` untargeted-priming qmd commands now work against the real CLI** ([#200](https://github.com/joestump/claude-plugin-sdd/issues/200)): the documented `qmd query --json -c {c} --limit 10000 --minScore 0` pattern failed three ways — `--minScore` is the MCP parameter name (CLI is `--min-score`), the result cap flag is `-n`, and an empty query is not a wildcard (qmd's query expansion garbles it). Untargeted mode now enumerates via `qmd ls` per a new `qmd-helpers.md` § "Exhaustive Retrieval (list-all)" section; topic mode puts the positional query first with kebab-case flags. The `qmd-helpers.md` CLI example is corrected to match.
- **Single-agent fallback in `/sdd:work` and `/sdd:review` no longer burns tokens on inline diff-reading** ([#201](https://github.com/joestump/claude-plugin-sdd/issues/201)): the TeamCreate-unavailable fallback paths now carry explicit context-hygiene rules — fork per-PR diff-read-and-verify to a subagent returning only a verdict + compact summary when subagents exist, otherwise default to `--name-only` plus targeted excerpts, and carry only outcome summaries between items. Canonical guidance lives in `harness-compat.md` § "Single-Agent Sequential Fallback".

- **ADR template pins the status enum** ([#218](https://github.com/joestump/claude-plugin-sdd/pull/218)): the MADR template showed a bare `status: proposed` without naming valid values, so a free-form or differently-capitalized value (`Accepted`, `done`) landed silently and broke `/sdd:status` transitions and `/sdd:list` rendering later.
- **Spec security topics satisfiable by governing-artifact reference** ([#220](https://github.com/joestump/claude-plugin-sdd/pull/220)): SPEC-0016 restated six security topics inline per spec with a single escape hatch; downstream, the same ADR was being restated verbatim in every spec. All six topics may now be satisfied by reference.
- **Docs cross-references key by artifact ID** ([#222](https://github.com/joestump/claude-plugin-sdd/pull/222)): `buildSpecMapping` keyed each spec's page under its ID *prefix* — the literal string `"SPEC"` — so each domain overwrote the last and one entry served the whole site; this repo's own checked-in `spec-mapping.json` mapped 24 specs to a single destination.
- **Docs cross-references route at the page the transform emits** ([#223](https://github.com/joestump/claude-plugin-sdd/pull/223)): the mapping assumed every spec domain holds both `spec.md` and `design.md`; a single-file domain is emitted as a flat page, so cross-references to it resolved to a route nothing writes — a silent 404 while broken links only warned.
- **Vendored docs-site fixes upstreamed** ([#224](https://github.com/joestump/claude-plugin-sdd/pull/224)): four fixes a downstream project made in its vendored copy of `sdd-content` and never sent back — nested anchors, dead graph links, baseUrl, ADR casing — reconciled end to end.
- **CVE-2026-9277** ([#225](https://github.com/joestump/claude-plugin-sdd/pull/225)): `shell-quote` 1.8.3 → 1.8.4 in `docs-site` (critical per scanner; present in the dependency tree, not confirmed reachable).
- **CVE-2026-54466** ([#226](https://github.com/joestump/claude-plugin-sdd/pull/226)): `websocket-driver` 0.7.4 → 0.7.5 in `docs-site`, same class.
- **`/sdd:graph` stops filing unparseable governing comments as absent** ([#230](https://github.com/joestump/claude-plugin-sdd/pull/230)): `_walk_code_files` matched only the *first* `Governing:` line and accepted only `//`, `#`, `<!--` openers, so a ticket-reference comment above a correct one filed the file as comment-less and falsely listed specs under "no implementing code."
- **`/sdd:graph` stops reporting mixed-direction edge pairs as cycles** ([#237](https://github.com/joestump/claude-plugin-sdd/pull/237)): `enables` points downstream while `extends` points upstream, but cycle detection ran one DFS over every edge type as if they all pointed the same way — a hard error that made every graph query verb refuse to run on the plugin's own repo. Edge direction is normalized before detection.
- **Skills cite shared-patterns sections, not the whole file** ([#231](https://github.com/joestump/claude-plugin-sdd/pull/231)): roughly 60 of 92 references to `references/shared-patterns.md` named no section, so the agent's only move was reading the whole ~800-line file — a measured ~6k tokens on top of every skill invocation. References now cite sections, and `/sdd:spec` stopped inlining a 42-line accessibility block verbatim.
## [5.2.1] — 2026-07-31

Bug-fix release addressing five issues reported from real-world adoption ([#190](https://github.com/joestump/claude-plugin-sdd/issues/190)–[#194](https://github.com/joestump/claude-plugin-sdd/issues/194)). No new features, no breaking changes.

### Fixed

- **`/sdd:check` and `/sdd:audit` can now invoke qmd from restricted contexts** ([#194](https://github.com/joestump/claude-plugin-sdd/issues/194)): both skills mandate qmd hybrid retrieval with an explicit never-fall-back rule, but were the only qmd-mandating skills whose `allowed-tools` lacked `Bash`. Wherever `allowed-tools` is enforced (e.g. subagents), they were required to do something they were not permitted to do. `Bash` added to both, matching the other six qmd-aware skills.
- **`/sdd:index` embed-prompt contradiction resolved** ([#194](https://github.com/joestump/claude-plugin-sdd/issues/194)): a leftover pre-v5 Rules bullet still mandated the three-way `AskUserQuestion` embed prompt on CPU machines, contradicting the Process section and ADR-0026's no-prompt policy. The bullet now describes the actual policy: background by default on CPU, `--foreground`/`--skip` override.
- **Reference paths fully qualified** ([#194](https://github.com/joestump/claude-plugin-sdd/issues/194)): all 190 bare `references/...` mentions of plugin-root reference docs across every `SKILL.md` now use `${CLAUDE_PLUGIN_ROOT}/references/...` — the bare form resolved against the invoking skill's own directory and 404'd (e.g. `/sdd:init`'s `claude-md-template.md` pointer). Skill-local references are unchanged.
- **Conflict-marker gate no longer false-positives on Markdown setext headings** ([#191](https://github.com/joestump/claude-plugin-sdd/issues/191)): `/sdd:review` treated any standalone `=======` line as a merge-conflict marker, rejecting PRs that merely added a seven-character setext-underlined heading (`Summary`, `Roadmap`, …). `=======` now counts only between a `<<<<<<<`/`>>>>>>>` pair in the same file; the bracketing markers still flag on their own. Spec, skill, README, and eval assertion updated together, with a new spec scenario covering the setext case.
- **Scaffolded docs-site first build no longer fails** ([#193](https://github.com/joestump/claude-plugin-sdd/issues/193)): three independent cold-start defects fixed — the `sdd-content` plugin now creates `docs-generated/` eagerly at construction (Docusaurus validates the directory before `loadContent()` runs); `@docusaurus/theme-mermaid` is pinned exactly to match core (a caret range resolved to 3.10.x and tripped the version-mismatch guard); and a `webpackbar` `^7` override guards against the 6.x/webpack ≥5.101 ProgressPlugin breakage.
- **Loop budget's built-in rate table flagged as a point-in-time snapshot** ([#192](https://github.com/joestump/claude-plugin-sdd/issues/192)): the compiled-in fallback rate table silently attributed $0 to models it didn't list, under-counting `dollars_estimate` exactly when a cost ceiling mattered. The table now carries an explicit freshness note, and implementations surface a once-per-run staleness notice whenever cost accounting runs on the built-in default with an active dollar ceiling — including the matched-but-drifted-prices case the unknown-model warning cannot detect.
- **`eval-tier3` CI job reads the real prompt corpus** ([#190](https://github.com/joestump/claude-plugin-sdd/issues/190)): the job pointed at a nonexistent `evals/tier3.json`; it now reads `evals/evals.json` filtered to the Tier 3 skill set, matching the other eval jobs.

## [5.2.0] — 2026-06-30

### Added

- **`/sdd:respond`**: new author-side skill that addresses review feedback already present on a PR — gathers review threads, requested-changes reviews, top-level comments, and failing CI; makes the code fixes on the PR branch and pushes; replies to each thread; and captures out-of-scope feedback as tracked follow-up issues. It judges requested changes against governing specs/ADRs (declining, with citation, those that would violate them) and never merges. Complements `/sdd:review` (reviewer-driven) by handling feedback that originated outside the plugin — the common human-review case. See [ADR-0034](docs/adrs/ADR-0034-author-side-pr-response-skill.md) and SPEC-0035. Functional and trigger evals added under `evals/`.

## [5.0.0] — 2026-05-15

### Breaking Changes

- **qmd is now a hard runtime dependency.** The plugin's read-side and authoring skills assume [qmd](https://github.com/tobi/qmd) is installed. `/sdd:init` performs a `command -v qmd` preflight check and refuses to set up a project if qmd is absent. Install with `npm install -g @tobilu/qmd` (or `bun install -g @tobilu/qmd`) before upgrading. See [ADR-0024](https://joestump.github.io/claude-plugin-sdd/decisions/0024-qmd-as-hard-dependency) for the full rationale.
- **Optional/fallback paths removed.** Skills no longer detect qmd at runtime and degrade — they assume qmd is present. Users on v4.x who do not want qmd should pin to the latest v4 release.
- **First-time embed downloads ~2&nbsp;GB of GGUF models** (EmbeddingGemma 300M, Qwen3-Reranker 0.6B, qmd-query-expansion 1.7B) into `~/.cache/qmd/`. Subsequent runs reuse the cache.

### Added

- **`/sdd:index`**: new skill that creates and maintains per-repo qmd collections (`{repo}-adrs`, `{repo}-specs`, `{repo}-code`, `{repo}-issues`). Runs on demand and is invoked by upgrade flows.
- **Tracker issues as a fourth qmd collection** ([ADR-0025](https://joestump.github.io/claude-plugin-sdd/decisions/0025-tracker-issues-as-fourth-qmd-collection)): tracker issues sync to `.sdd/issues/` and are indexed alongside ADRs, specs, and code so planning and review skills can find prior work.
- **Tiered index freshness** ([ADR-0026](https://joestump.github.io/claude-plugin-sdd/decisions/0026-tiered-index-freshness-strategy)): each skill belongs to one of four freshness tiers and refreshes the qmd index accordingly — Tier 1 (post-mutation), Tier 2 (session-start, in `/sdd:prime`), Tier 3 (drift skills), Tier 4 (sprint skills always sync issues on entry, subject to a 5-minute dedup window).
- **`/sdd:prime` non-authoritative artifact filtering** ([ADR-0027](https://joestump.github.io/claude-plugin-sdd/decisions/0027-non-authoritative-artifact-filtering-in-prime)): ADRs and specs with status `superseded`, `deprecated`, or `rejected` are excluded from the primed context and listed in a footer with `superseded-by` transition links. Topic mode still surfaces them with a `⚠` badge.
- **qmd-aware authoring skills**: `/sdd:adr`, `/sdd:spec`, and `/sdd:status` now pre-search the artifact corpus before mutating, so users see candidate edges (supersedes, related, extends) and prior decisions on the same topic instead of guessing.
- **qmd-aware drift skills**: `/sdd:check` and `/sdd:audit` use top-K retrieval per target file/scope, replacing the corpus-wide scan path for substantially better signal on mature repos.
- **qmd-aware planning and implementation**: `/sdd:plan` and `/sdd:work` retrieve relevant existing code and prior issues before sizing stories or writing implementations, so duplicate work surfaces early.
- **`/sdd:discover` pre-search**: rules out duplicate decisions before drafting ADR candidates from existing code.

### Changed

- `/sdd:prime` topic mode (`/sdd:prime <topic>`) uses qmd hybrid retrieval rather than reading every artifact and filtering semantically.
- `/sdd:prime` runs a Tier 2 `qmd update` on entry (cheap mtime scan); skipped if the index was touched within 60 seconds.

### Documentation

- New "Prerequisites" section in [Getting Started](./guides/getting-started) covering qmd installation.
- `/sdd:prime` command reference updated for v5 behavior. Other skill entries in [Skills](./skills/) describe v4 behavior and will be updated in a follow-up doc PR.

### Notes for upgrading

1. Install qmd: `npm install -g @tobilu/qmd`.
2. Run `/sdd:init` to confirm the preflight passes; CLAUDE.md is rewritten only if needed.
3. Run `/sdd:index` to build the per-repo collections (this is when the GGUF models download).
4. Resume normal workflow — every qmd-aware skill now uses retrieval transparently.

If you cannot install qmd, stay on v4.x.
